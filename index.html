Both frames paint a plain white box. If A looks dark but B stays white, the browser is force-darkening pages (several browsers ship an automatic dark mode for web content, often behind a settings flag). If both are dark, an extension or an OS color filter / inversion is likely at work. Scripts can’t read these pixels — trust your eyes.

Change log 


    

      What can / can’t be detected
      
    
        
  • OS vs browser can’t be separated. prefers-color-scheme is whatever the browser decides to expose:
          it passes the OS setting through unless the browser overrides it (many browsers have their own appearance or
          website-theme setting; some only follow the system).
    • 
        
  • The UA rendering row resolves the Canvas system color under color-scheme: light dark —
          an independent read of which palette the browser uses for built-in widgets.
    • 
        
  • Privacy modes lie on purpose: anti-fingerprinting settings and privacy-hardened browsers may always report light.
    • 
        
  • Auto-dark / forced-dark modes usually don’t change computed styles, so only the visual self-test can reveal them.
    • 
        
  • Servers can get the same value via the Sec-CH-Prefers-Color-Scheme client hint (some engines only, opt-in with Accept-CH) — not visible from a static page.
    • 
        
  • OS color filters, smart or classic inversion, night light / blue-light filters and monitor settings sit below the browser and are invisible to it
          (except where the browser supports inverted-colors).
